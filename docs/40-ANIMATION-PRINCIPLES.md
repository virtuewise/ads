# 40 — Animation Principles & Procedural Motion

**Status: 🟡 (keyframe + stagger + ease nodes exist; procedural motion, physics, and the full easing library are ⬜) · Code: `engine/nodes.ts`, `engine/timeline.ts` → target: `engine/motion/*`**

> Beyond keyframes, professional motion design needs **procedural animation** — motion generated by
> rules rather than hand-placed keyframes. Today the only procedural node is `StaggerNode` (linear
> stagger). This document specifies the full motion toolkit.

---

## 1. The three animation paradigms

| Paradigm | Mechanism | Use |
|---|---|---|
| **Keyframed** | hand-placed keyframes + easing | precise, authored motion |
| **Procedural** | rules generate motion from time | loops, randomness, physics |
| **Reactive** | motion driven by external signals | audio, mouse, sensors |

The three compose: a keyframed base + a procedural offset + a reactive modulation.

## 2. Procedural motion nodes (target)

### 2.1 Oscillator

```typescript
// Sine, square, triangle, sawtooth waves
interface OscillatorNode {
  waveform: 'sine' | 'square' | 'triangle' | 'sawtooth';
  frequency: number;    // Hz
  amplitude: number;
  phase: number;        // offset
  output: number;       // -amplitude … +amplitude
}
```

Use: pulsing, breathing, cycling — anything periodic.

### 2.2 Noise

```typescript
// Perlin / simplex / white noise
interface NoiseNode {
  type: 'perlin' | 'simplex' | 'white';
  scale: number;        // spatial frequency
  octaves: number;      // fractal octaves
  evolution: number;    // time evolution speed
  output: number;       // 0–1
}
```

Use: organic motion, randomness, texture, camera shake.

### 2.3 Physics (spring & damp)

```typescript
interface SpringNode {
  target: number;
  stiffness: number;    // spring constant
  damping: number;      // 0–1 (1 = no oscillation)
  mass: number;
  output: number;
}
```

Use: bouncy settles, overshoot, natural motion. The spring integrates per-frame:

```
velocity += (target - value) * stiffness / mass
velocity *= (1 - damping)
value += velocity
```

### 2.4 Particle system

GPU-accelerated particles ([27](27-EFFECTS-LIBRARY.md#particle-system-a-flagship-effect)):

```typescript
interface ParticleNode {
  count: number;
  emitter: 'point' | 'line' | 'shape' | 'image';
  forces: ('gravity' | 'wind' | 'turbulence' | 'vortex' | 'attract')[];
  lifetime: [number, number];
  size: [number, number];
  color: ColorRange;
  blendMode: BlendMode;
}
```

### 2.5 Loop

```typescript
interface LoopNode {
  input: number;        // progress 0–1
  mode: 'loop' | 'pingpong' | 'once';
  output: number;       // looped progress
}
```

### 2.6 Delay & velocity

```typescript
interface DelayNode { input: number; delay: number; output: number; }
interface VelocityNode { input: number; output: number; }  // derivative
```

## 3. The easing library (target)

The current system has 4 quadratic easings. The full library:

### 3.1 Polynomial

| Name | Formula | Character |
|---|---|---|
| `quadIn/Out/InOut` | `t²` | gentle |
| `cubicIn/Out/InOut` | `t³` | moderate |
| `quartIn/Out/InOut` | `t⁴` | strong |
| `quintIn/Out/InOut` | `t⁵` | extreme |

### 3.2 Trigonometric & exponential

| Name | Formula | Character |
|---|---|---|
| `sineIn/Out/InOut` | `1-cos(t·π/2)` | very gentle |
| `circIn/Out/InOut` | `sqrt(1-t²)` | dramatic |
| `expoIn/Out/InOut` | `2^(10(t-1))` | exponential |

### 3.3 Overshoot & spring

| Name | Character |
|---|---|
| `backIn/Out/InOut` | overshoots then settles |
| `elasticIn/Out/InOut` | spring oscillation, decaying amplitude |
| `bounceIn/Out/InOut` | bouncing ball |

### 3.4 Custom bezier

```typescript
interface CubicBezierEasing {
  p1: [number, number];   // control point 1 (x: 0–1, y: any)
  p2: [number, number];   // control point 2
}
```

This is After Effects' "Easy Ease" — a cubic bezier where the handle positions define the curve.

## 4. The graph editor (target)

A bezier-curve editor (like After Effects' Graph Editor):

- **Speed graph:** value vs time, handles control velocity.
- **Value graph:** value vs time, handles control interpolation.
- **Edit:** drag handles, numeric input, preset easings.
- **Scale:** time-stretch preserves velocity.

## 5. Audio-reactive motion

Motion driven by audio analysis ([25](25-AUDIO.md)):

```typescript
interface AudioReactiveNode {
  source: 'audio' | 'music' | 'dialogue';
  band: 'bass' | 'mid' | 'treble' | 'full';
  property: 'scale' | 'position' | 'rotation' | 'opacity' | 'custom';
  sensitivity: number;
  smoothing: number;
  output: number;
}
```

The audio engine computes a per-frame FFT, extracts the band energy, and maps it to a property.
This is the signature "audio-reactive" motion-design effect.

## 6. Expression-driven motion

Expressions ([39](39-SCRIPTING-AND-EXPRESSIONS.md)) can drive procedural motion:

```
// A camera shake driven by noise
position.x = noise(time * 2) * 10
position.y = noise(time * 2 + 100) * 10

// A scale pulse driven by audio bass
scale = 1 + audio.bass * 0.5
```

## 8. Verification

| Property | Test |
|---|---|
| Oscillator periodicity | `osc(t) == osc(t + period)` |
| Noise determinism | same seed → same noise sequence |
| Spring convergence | spring reaches target and settles |
| Easing endpoints | every easing maps 0→0 and 1→1 |
| Bezier monotonicity | a monotone bezier produces no overshoot |
| Audio reactivity | a loud frame produces a larger value than a quiet one |
| Export parity | procedural motion is identical in viewport and export |
